🔷 SECTION 1: PROJECT OVERVIEW
Q1. What is your project about?
My project is an E-Municipal Portal for Newasa Municipal Corporation. It is a web-based system that digitizes municipal services. Citizens can apply for government services (birth certificate, caste certificate, etc.), file complaints, pay utility bills, and give feedback — all online. Admins manage departments, employees, services, and live news. Employees process citizen requests.
Q2. What problem does your project solve?
Earlier, citizens had to physically visit the municipal office for every service — time-consuming and inefficient. Our portal brings all services online, reducing manual work, paperwork, corruption, and waiting time. Citizens can track their requests and complaints from home.
Q3. Who are the users (roles) of this system?
There are 3 types of users:
  • Admin – Manages departments, employees, services, complaints, bills, and live news
  • Citizen – Applies for services, files complaints, pays utility bills, gives feedback
  • Employee – Views and processes service requests of their department
Q4. What are the main modules of your project?
  • User Authentication (Login/Register with JWT + Google OAuth)
  • Department Management
  • Employee Management
  • Complaint Management (with image upload)
  • Service Requests (Certificates, etc.)
  • Utility Bill Management
  • Feedback System
  • Live News Ticker (Admin-managed)
  • Admin Dashboard (statistics)

Q6. Why did you choose React for the frontend?
React is a component-based library that allows building reusable UI components. It has fast rendering via Virtual DOM, large community support, and works well with REST APIs using Axios. Vite gives very fast build and hot-reload during development.
Q7. Why did you choose ASP.NET Core for the backend?
ASP.NET Core is a high-performance, cross-platform framework for building REST APIs. It has built-in support for dependency injection, JWT authentication, authorization policies, and integrates natively with Entity Framework Core.
Q8. Why PostgreSQL?
PostgreSQL is a powerful, open-source relational database. It supports complex queries, foreign keys, and transactions. It is free, reliable, and works well with EF Core via the Npgsql provider.
Q9. What is Entity Framework Core?
EF Core is an ORM (Object-Relational Mapper). Instead of writing raw SQL, we define C# model classes (e.g., Citizen, Department) and EF Core automatically generates and executes SQL. It also handles migrations — creating/updating database tables when the model changes.

Q12. What is a Migration in EF Core?
A migration is a snapshot of database model changes. When we add a new model (e.g., News), we run: 
dotnet ef migrations add AddNewsTable
dotnet ef database update
The first command creates a migration file with SQL instructions. The second applies it to PostgreSQL.
Q13. What is normalization?
Normalization organizes the database to reduce data redundancy:
  • 1NF – Atomic values in each column
  • 2NF – No partial dependencies
  • 3NF – No transitive dependencies
Our database follows 3NF — instead of storing department name in every employee record, we store DNo (foreign key) referencing the Department table.
🔷 SECTION 4: AUTHENTICATION & SECURITY
Q14. What is JWT? How does it work in your project?
JWT (JSON Web Token) is a compact, signed token for transmitting user identity. In our project:
  • User logs in with email + password
  • Backend verifies credentials and generates a JWT containing UserId, Name, Email, Role
  • JWT is sent to frontend and stored in localStorage
  • Every API request sends the JWT in Authorization: Bearer <token> header
  • Backend validates the token and allows/denies access based on role
Q15. How are passwords stored? Are they secure?
Passwords are never stored in plain text. We use SHA-256 hashing: 
Convert.ToBase64String(SHA256.HashData(Encoding.UTF8.GetBytes(password)))
Hashing is one-way — it cannot be reversed. During login, we hash the entered password and compare it with the stored hash.
Q16. What is Role-Based Authorization?
Role-based authorization restricts API endpoints based on the user's role: 
[Authorize(Roles = "Admin")]  // only Admin
[Authorize]                    // any logged-in user
[AllowAnonymous]              // no login needed
The role is embedded inside the JWT token and verified on every request.
Q17. What is Google OAuth? How is it used?
Google OAuth allows citizens to log in using their Google account. Process:
  • Google sends an access token to our frontend
  • Frontend sends it to POST /api/auth/google
  • Backend calls Google's userinfo API to get email and name
  • If citizen doesn't exist, they are auto-registered
  • Our own JWT is generated and returned
Q18. What is the difference between Authentication and Authorization?
  • Authentication = Verifying WHO you are (login → get JWT)
  • Authorization = Verifying WHAT you can do (Admin can delete, Citizen cannot)
In ASP.NET Core, [Authorize] first checks if the token is valid (authentication), then checks the role claim (authorization).
🔷 SECTION 5: BACKEND / API
Q19. What is a REST API?
REST (Representational State Transfer) API is a web service using HTTP methods:
  • GET — Read data
  • POST — Create new data
  • PUT — Update existing data
  • DELETE — Remove data
Our backend exposes these endpoints to the React frontend.

Q21. What is CORS and why is it needed?
CORS (Cross-Origin Resource Sharing) is a browser security feature that blocks requests from one origin (localhost:5173) to another (localhost:5000). We configure CORS in Program.cs to allow the frontend to call the backend API.
Q22. What is Dependency Injection?
DI is a pattern where a class receives its dependencies from outside. In ASP.NET Core, we register services in Program.cs: 
builder.Services.AddDbContext<ApplicationDbContext>(...);
Any controller can then receive ApplicationDbContext via its constructor automatically — making code loosely coupled and testable.
🔷 SECTION 6: FRONTEND
Q23. What is React and how does it work?
React is a JavaScript library for building UIs using components. Each component has state (data) and props (inputs). When state changes, React re-renders only the affected part using the Virtual DOM. We use hooks like useState, useEffect, useContext.
Q24. What is useState and useEffect?
  • useState — declares a reactive variable. When it changes, the component re-renders.
    const [news, setNews] = useState([]);
  • useEffect — runs side effects (like API calls) after render.
    useEffect(() => { fetchNews(); }, []); // runs once on mount
Q25. What is Context API? How did you use it?
Context API allows sharing state globally across components without passing props manually. We use AuthContext to store the logged-in user's token, role, and name — accessible from any component (Navbar, sidebar, protected routes).
Q26. How does the Live News ticker work?
  • On home page load, useEffect fetches active news from GET /api/news
  • Results stored in newsItems state
  • If API fails or empty, a FALLBACK_NEWS array is shown
  • A second useEffect runs setInterval every 4 seconds to increment newsIdx
  • Ticker displays newsItems[newsIdx] — cycling through all items
🔷 SECTION 7: FEATURES
Q27. Explain the Complaint module.
Citizens file complaints with title, description, category, optional image, and department. Stored with status Pending. Employees see complaints of their department and update status to In Progress or Resolved. Admin views all complaints.
Q28. Explain the Service Request module.
Citizens apply for services (Birth Certificate, Caste Certificate, Domicile, etc.). They select a service, upload documents, and pay the fee. Admin reviews and changes status: Pending → Approved / Rejected.
Q29. Explain the Utility Bill module.
Admin generates bills for Water, Electricity, and Property Tax. Each bill has amount, due date, and payment status (Paid/Unpaid). Multiple services can be in one bill via the BillService junction table. Citizens view bills under "My Bills" and "Utility Bills" in the sidebar.
Q30. What is the Admin Dashboard?
Shows key statistics: total departments, employees, complaints, service requests. Displays recent service requests with status badges and provides quick navigation to all management sections.

Q31. What SDLC model did you follow?

  • Design — created ER diagram, UI wireframes
  • Development — built backend API, then frontend module by module

Q32. What is MVC architecture?
MVC separates the application into 3 layers:
  • Model — Data/business logic (C# model classes + EF Core)
  • View — UI (React components)
  • Controller — Handles HTTP requests (ASP.NET Core controllers)
React is the View, ASP.NET controllers are Controller, EF Core models are Model.
Q33. What is a foreign key?
A foreign key is a column in one table that references the primary key of another table, establishing a relationship. For example, Employee.DNo is a foreign key referencing Department.DNo.
🔷 SECTION 9: TRICKY VIVA QUESTIONS
Q34. What happens if the JWT token expires?
Our JWT tokens are valid for 8 hours. After expiry, API calls return 401 Unauthorized. The frontend redirects the user to the login page. The user must log in again to get a new token.
Q35. Can two citizens have the same email?
No. The backend checks for duplicate emails during registration: 
if (await _context.Citizens.AnyAsync(c => c.Email == dto.Email))
    return BadRequest("Email already exists");
Q36. What happens when Admin deletes a department?
We perform cascade deletion manually:
  • Delete all ServiceRequests of that department's services
  • Delete all Services of that department
  • Delete all Employees of that department
  • Delete all Complaints of that department
  • Delete the Department itself
This avoids foreign key constraint violations.
Q37. What is the difference between PUT and PATCH?
PUT replaces the entire resource with new data. PATCH updates only specific fields. We use PUT in our project — we send the full object when updating (e.g., updating a news item sends both title and active status).
Q38. Why use Axios instead of fetch?
Axios automatically:
  • Parses JSON responses
  • Attaches the Authorization header globally via interceptor
  • Has better error handling with err.response
We configured an Axios instance in api/axios.js with baseURL: 'http://localhost:5000/api' so we don't repeat the URL everywhere.
Q39. How did you handle image uploads for complaints?
The complaint form sends a multipart/form-data request with the image file. The backend saves the file to wwwroot/uploads and stores the file path in Complaint.imageUrl. The frontend displays it using http://localhost:5000{imageUrl}.
Q40. What is database seeding?
Seeding means pre-populating the database with default data. We have a SeedController with /api/seed/init that creates the default Admin, Citizen, Employee, and basic services (Property Tax, Water, Electricity) for testing.
Q41. What security measures did you implement?
  • Password hashing — SHA-256, never stored in plain text
  • JWT tokens — stateless, signed, expire after 8 hours
  • Role-based access — [Authorize(Roles = "Admin")] on sensitive endpoints
  • CORS policy — only allows requests from the frontend origin
  • Input validation — DTOs validate required fields before processing
Q42. What is the fallback news list on the home page?
If the API is unreachable or returns no news, a hardcoded FALLBACK_NEWS array is shown in the ticker so the home page never appears empty. Once the API returns data, the fallback is replaced with real news from the database.
Q43. What is localStorage vs sessionStorage?
localStorage persists even after closing the browser tab. sessionStorage clears when the tab is closed. We use localStorage to store the JWT token so the user stays logged in between sessions.
