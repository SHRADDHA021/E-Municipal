⚡ SECTION 1: FRONTEND — React, Vite, JavaScript (Q1–Q50)
Q1. What is React?
React is an open-source JavaScript library by Facebook for building interactive user interfaces. It uses a component-based architecture — the UI is split into reusable pieces called components. React uses a Virtual DOM to efficiently update only changed parts of the real DOM, making it very fast.
Q2. What is Vite and why did you use it?
Vite is a modern frontend build tool. It serves files using native ES modules during development, making it much faster than Create React App. Commands: npm run dev (start dev server on localhost:5173), npm run build (production build).
Q3. What is JSX?
JSX (JavaScript XML) is a syntax extension that lets you write HTML-like code inside JavaScript. It is transpiled to React.createElement() calls by Babel. Example: <div className="box">Hello</div>
Q4. What is a component in React?
A component is a reusable, independent piece of UI. In our project we use functional components. Example: function ManageNews() { return <div>...</div>; }. Components receive props as input and return JSX.
Q5. What is the difference between props and state?
  • Props: Read-only data passed from parent to child component. Cannot be changed by the child.
  • State: Internal data of a component. When state changes, the component re-renders. Managed with useState.
Q6. What is useState?
useState is a React hook to add state to a functional component.
const [newsItems, setNewsItems] = useState([]);
// newsItems = current value, setNewsItems = updater function
When setNewsItems is called, the component re-renders with the new value.
Q7. What is useEffect?
useEffect runs side effects (API calls, subscriptions, timers) after the component renders.
useEffect(() => {
  fetchNews(); // runs after first render
}, []); // [] = run only once (on mount)
If the dependency array has a value, it re-runs when that value changes.
Q8. What happens when state changes in React?
React re-renders the component — it re-executes the function and compares the new Virtual DOM with the old one (diffing). Only the changed DOM nodes are updated in the real browser DOM. This is called reconciliation.
Q9. What is the Virtual DOM?
The Virtual DOM is a lightweight JavaScript copy of the real DOM kept in memory. When state changes, React updates the Virtual DOM first, then compares it with the previous version (diffing), and updates only the changed parts in the real DOM — making updates fast and efficient.
Q10. What is React Router?
React Router is a library for client-side navigation — switching pages without a full browser reload. We define routes in App.jsx:
<Route path="/citizen" element={<CitizenDashboard />} />
<Route path="/admin/news" element={<ManageNews />} />
Q11. What is useNavigate?
useNavigate is a React Router hook for programmatic navigation.
const navigate = useNavigate();
navigate('/citizen'); // redirect to citizen dashboard
Used after login to redirect users to their dashboard based on role.
Q12. What is the Context API?
Context API is a way to share data globally across components without prop drilling. We use AuthContext to store: JWT token, user role, user name, userId. Any component can read this using useContext(AuthContext).
Q13. What does AuthContext contain in your project?
AuthContext stores: token (JWT string), role (Admin/Citizen/Employee), name (user's name), userId. It also provides login() function (saves to localStorage) and logout() function (clears localStorage and redirects to home).
Q14. What is localStorage? Why do you use it?
localStorage is a browser storage that persists data even after closing the browser tab. We store the JWT token in localStorage so the user stays logged in between sessions. Cleared on logout.
Q15. What happens when user refreshes the page?
When the page refreshes, all React state is lost. But since the JWT token is in localStorage, AuthContext reads it on startup and restores the user's session. The user does NOT get logged out on refresh.
Q16. What is Axios? How is it configured?
Axios is a JavaScript HTTP client. We created a configured instance in api/axios.js:
import axios from 'axios';
const api = axios.create({ baseURL: 'http://localhost:5000/api' });
api.interceptors.request.use(config => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
This automatically attaches the JWT to every request.
Q17. What is an Axios interceptor?
An interceptor runs before every request or after every response. We use a request interceptor to automatically add Authorization: Bearer <token> header to every API call — so we don't have to do it manually in each component.
Q18. What is a Protected Route?
A protected route checks if the user is logged in (and has the correct role) before allowing access. If not authenticated, it redirects to login. In our project, routes like /admin, /citizen are protected using AuthContext role checks.
Q19. What is the difference between class components and functional components?
Class components use class MyComp extends React.Component with lifecycle methods like componentDidMount. Functional components are simpler JavaScript functions — we use hooks (useState, useEffect) instead. We use only functional components in our project.
Q20. What is useRef?
useRef creates a mutable reference that persists across renders without causing re-render. Used in our project to reference the services dropdown element to detect outside clicks:
const servicesRef = useRef(null);
if (servicesRef.current && !servicesRef.current.contains(e.target))
  setShowServices(false);
Q21. What is CSS-in-JS? How did you use it?
CSS-in-JS means writing styles directly as JavaScript objects inside component files. Example:
const inp = { display:'block', width:'100%', padding:'0.65rem',
  border:'1.5px solid #e2e8f0', borderRadius:'0.6rem' };
Passed to elements with style={inp}. Avoids separate CSS files for admin pages.
Q22. What is the difference between == and === in JavaScript?
== compares values after type conversion (loose equality). === compares both value and type (strict equality). Always prefer ===. Example: 1 == "1" is true, but 1 === "1" is false.
Q23. What is async/await?
async/await is syntax for handling Promises (asynchronous operations) without chaining .then(). Example:
const fetchNews = async () => {
  const { data } = await api.get('/news');
  setNews(data);
};
Errors are caught with try/catch.
Q24. What is the map() function? How did you use it?
Array.map() transforms each element and returns a new array. Used to render lists in JSX:
{newsList.map((n, idx) => (
  <tr key={n.id}><td>{n.title}</td></tr>
))}
The key prop is required for React to track list items.
Q25. What is the key prop in React lists?
The key prop is a unique identifier for each item in a list. React uses it to efficiently update the DOM — identifying which items were added, removed, or moved. Without keys, React re-renders the entire list on any change.
Q26. What is conditional rendering?
Rendering different JSX based on conditions. We use:
  • {condition && <Component />} — render if true
  • {condition ? <A /> : <B />} — ternary
Example: {toast && <div>{toast}</div>} shows toast only when it has a value.
Q27. What is the spread operator? How did you use it?
The spread operator ... copies properties of an object or elements of an array. Used to update form state without losing other fields:
setForm({ ...form, IsActive: e.target.checked });
// copies all form fields, only updates IsActive
Q28. What is destructuring in JavaScript?
Destructuring extracts values from objects or arrays into variables:
const { data } = await api.get('/news'); // object destructuring
const [count, setCount] = useState(0); // array destructuring
Q29. What is a callback function?
A function passed as an argument to another function, called later. Example: onClick={() => handleDelete(id)} — the arrow function is a callback passed to the onClick event handler.
Q30. What is setInterval? How is it used in the news ticker?
setInterval runs a function repeatedly at a set interval. In the news ticker:
const t = setInterval(() => 
  setNewsIdx(i => (i + 1) % newsItems.length), 4000);
return () => clearInterval(t); // cleanup on unmount
Changes the displayed news every 4 seconds. The cleanup prevents memory leaks.
Q31. What is the Layout component?
Layout is a wrapper component that provides the sidebar navigation based on the user's role. Every admin page is wrapped in <Layout>, which reads the role from AuthContext and renders the correct sidebar links (Admin links vs Citizen links vs Employee links).
Q32. What is event.preventDefault()?
Prevents the default browser behavior for an event. Used in form submissions:
const handleSubmit = async (e) => {
  e.preventDefault(); // prevents page reload on form submit
  // our custom logic
};
Q33. What is a toast notification?
A toast is a small temporary popup message giving feedback to the user (success/error). We implement it with a state variable:
const showToast = (msg) => {
  setToast(msg);
  setTimeout(() => setToast(''), 3500); // auto-dismiss after 3.5s
};
Q34. How does the login form work?
  • User fills email, password, role (Admin/Citizen/Employee)
  • On submit: POST /api/auth/login with credentials
  • API returns: token, role, name, userId
  • These are saved to localStorage and AuthContext
  • User is redirected based on role: /admin, /citizen, or /employee
Q35. What is Google OAuth in the frontend?
We use @react-oauth/google library. The GoogleLogin component shows a Google sign-in button. On success, Google returns a credential (access token). We send it to POST /api/auth/google and get back our own JWT token.
Q36. What is VITE_API_BASE_URL?
It is an environment variable in the .env file accessed as import.meta.env.VITE_API_BASE_URL. In Vite, all env variables must start with VITE_ to be exposed to the frontend. Used in HomePage to build the API URL fallback.
Q37. What is a modal dialog?
A modal is a popup overlay that blocks interaction with the rest of the page until dismissed. We build custom modals with fixed positioning:
style={{ position:'fixed', top:0, left:0, width:'100vw', 
height:'100vh', background:'rgba(0,0,0,0.6)' }}
Used for delete confirmations in all admin pages.
Q38. What is the difference between null, undefined, and empty string?
  • null — intentionally empty value
  • undefined — variable declared but not assigned
  • "" — string with no characters
In forms, we use || null to convert empty strings to null before sending to API.
Q39. What is array.filter()?
filter() returns a new array with elements that pass a condition:
newsList.filter(n => n.isActive).length // count active news items
Used in the ManageNews page to show active count badge.
Q40. What is optional chaining (?.) in JavaScript?
Optional chaining safely accesses nested properties without throwing an error if intermediate values are null/undefined:
err?.response?.data // returns undefined if err or response is null
// instead of: err && err.response && err.response.data
Q41. How do you handle API errors in the frontend?
try {
  const { data } = await api.post('/news', payload);
  showToast('Success!');
} catch (err) {
  showToast('Error: ' + (err?.response?.data || 'Failed'));
}
We show the server's error message to the user via toast notification.
Q42. What is a form controlled component?
A controlled component has its form data managed by React state. Every input change updates state:
<input value={form.Title} onChange={e => setForm({...form, Title: e.target.value})} />
React is the "single source of truth" for the form data.
Q43. What is the difference between GET and POST requests in the frontend?
  • GET: Fetches data. No request body. Example: api.get('/news')
  • POST: Sends data to create something. Has a request body (JSON). Example: api.post('/news', payload)
Q44. What is multipart/form-data?
A content type for forms that include file uploads. Used for complaint image upload:
const formData = new FormData();
formData.append('title', title);
formData.append('image', file);
api.post('/complaints', formData); // axios auto-sets content-type
Q45. How does the sidebar know which links to show?
The Layout component reads role from AuthContext. A navMap object maps each role to its links:
const navMap = {
  Admin: [ {label:'Dashboard', path:'/admin'}, ... ],
  Citizen: [ {label:'Dashboard', path:'/citizen'}, ... ]
}
It renders navMap[role] as sidebar links.
Q46. What is CSS Flexbox?
Flexbox is a CSS layout model for arranging items in rows or columns. Used throughout our project:
display:'flex', justifyContent:'space-between', alignItems:'center'
Creates the header layout with title on left and Add button on right.
Q47. What is CSS Grid?
CSS Grid is a 2D layout system. Used for the department cards:
display:'grid', gridTemplateColumns:'repeat(auto-fill, minmax(280px, 1fr))'
Creates a responsive grid that auto-fills columns based on available width.
Q48. What is the fallback news list?
If the API is unreachable or returns empty, a hardcoded FALLBACK_NEWS array shows in the home page ticker so it never looks empty. Once API returns data, fallback is replaced. This ensures good UX even during API downtime.
Q49. What is the purpose of the .env file in the frontend?
The .env file stores environment-specific variables that should not be hardcoded. In our project: VITE_GOOGLE_CLIENT_ID (Google OAuth client ID). Vite reads this and makes it available via import.meta.env.VITE_GOOGLE_CLIENT_ID.
Q50. What is page-level code splitting in React?
Each page (ManageNews, Dashboard, etc.) is a separate component file imported in App.jsx. Vite automatically splits these into separate JS chunks, so only the code for the current page is loaded — improving performance via lazy loading.
⚡ SECTION 2: BACKEND — ASP.NET Core 8 & C# (Q51–Q100)
Q51. What is ASP.NET Core?
ASP.NET Core is a cross-platform, high-performance framework by Microsoft for building cloud-connected, internet-connected applications like web apps, IoT apps, and mobile backends. We use it to build a REST API.
Q52. What is C#?
C# is a modern, object-oriented, and type-safe programming language developed by Microsoft. It runs on the .NET framework and is the primary language used to build our backend logic, models, and controllers.
Q53. What is a REST API?
REST (Representational State Transfer) is an architectural style for APIs. A REST API uses HTTP requests to GET, PUT, POST and DELETE data. It relies on a stateless, client-server communication protocol, usually transmitting data in JSON format.
Q54. What is the role of Program.cs?
Program.cs is the entry point of an ASP.NET Core application. It configures the application's services (like Dependency Injection, Database context, Authentication, CORS) and the request pipeline (middleware).
Q55. What is Dependency Injection (DI)?
DI is a software design pattern where objects receive their dependencies from an external source rather than creating them internally. ASP.NET Core has built-in DI. We register services in Program.cs and inject them into controllers via constructors.
Q56. What is the Controller pattern?
Controllers handle incoming HTTP requests and send responses back to the caller. They group related action methods. E.g., NewsController handles all endpoints related to the News feature (GET /news, POST /news, etc.).
Q57. What is an Action Method?
An action method is a method within a controller that corresponds to a specific HTTP endpoint and verb (e.g., GET, POST). It performs the necessary logic and returns an IActionResult.
Q58. What does IActionResult do?
IActionResult is an interface representing the result of an action method. It allows returning different HTTP status codes alongside data. Example: return Ok(data) (200), return NotFound() (404), or return BadRequest("Error") (400).
Q59. What are Routing Attributes?
Attributes like [Route("api/[controller]")] and [HttpGet("{id}")] define the URL pattern for controllers and actions. [controller] dynamically maps to the controller's name (e.g., NewsController becomes /api/news).
Q60. What is Entity Framework Core (EF Core)?
EF Core is a lightweight, cross-platform ORM (Object-Relational Mapper) for .NET. It lets us interact with the database using C# objects instead of writing raw SQL queries.
Q61. What is ApplicationDbContext?
It is a class inheriting from DbContext in EF Core. It acts as a bridge between our models and the database. It contains DbSet<TEntity> properties for each table (e.g., DbSet<News> News) and configures relationships.
Q62. What is a Model in ASP.NET Core?
A model is a C# class representing the shape of data. In EF Core, entity models correspond to database tables (e.g., Citizen.cs maps to the "Citizens" table), and properties map to columns.
Q63. What is a DTO (Data Transfer Object)?
A DTO is an object used to pass data between the frontend and backend. It hides internal database details. For example, CitizenRegisterDto only contains fields needed for registration, preventing over-posting and hiding password hashes.
Q64. How do you handle file uploads?
File uploads use IFormFile in ASP.NET Core. In the complaint controller, we receive the image, generate a unique filename, save it to the wwwroot/uploads folder, and store the relative URL path in the database.
Q65. What is the wwwroot folder?
wwwroot is the web root directory in an ASP.NET Core project. It stores static files like images, CSS, and JS. We enabled static files in Program.cs via app.UseStaticFiles() so the frontend can access uploaded images.
Q66. What is JWT Authentication?
JSON Web Token (JWT) is used for stateless authentication. Upon valid login, the server creates a token containing user claims (ID, Role, Email) signed with a secret key. The client sends this token in the Authorization header for protected routes.
Q67. How is JWT generated in your code?
Using JwtSecurityTokenHandler and SymmetricSecurityKey. We read the secret key from appsettings.json, define claims, set an expiration (e.g., 8 hours), and generate the signed string token in AuthController.
Q68. What are Claims in JWT?
Claims are pieces of information about the user embedded in the token. We use claims like ClaimTypes.NameIdentifier (UserId), ClaimTypes.Email, and ClaimTypes.Role. This prevents database lookups on every request just to know who the user is.
Q69. How do you protect endpoints?
We use the [Authorize] attribute. [Authorize] requires any valid token. [Authorize(Roles = "Admin")] specifically requires the token to contain the Admin role claim. [AllowAnonymous] allows unauthenticated access.
Q70. How are passwords hashed?
We use SHA-256 hashing. Passwords are never saved as plain text. The HashPassword method converts the plain string into bytes, computes the SHA-256 hash, and saves the Base64 representation. During login, the input is hashed and compared to the DB hash.
Q71. What is CORS?
Cross-Origin Resource Sharing (CORS) is a security feature. By default, browsers block requests to a different domain. Since our frontend is on port 5173 and backend on 5000, we configure app.UseCors() to explicitly allow our frontend origin.
Q72. What is Middleware?
Middleware are software components assembled into the application pipeline to handle requests and responses. Examples: Routing, Authentication, Authorization, CORS. The order of middleware in Program.cs matters.
Q73. What is appsettings.json?
It is a configuration file storing settings like the database connection string, JWT secret keys, issuer, and audience. Settings can vary by environment (e.g., appsettings.Development.json).
Q74. How do you prevent Over-Posting attacks?
By using DTOs instead of entity models as input parameters in controllers. DTOs only contain the properties the client is allowed to send, ignoring sensitive internal fields like Id or PasswordHash.
Q75. What is asynchronous programming (async/await)?
It allows non-blocking execution. When the backend calls the database (e.g., await _context.Citizens.ToListAsync()), the thread is freed up to handle other requests until the DB responds, improving scalability.
Q76. What is the difference between IEnumerable and IQueryable?
IQueryable builds a SQL query and executes it in the database (efficient for filtering). IEnumerable pulls all data into memory first and then filters it (inefficient for large DBs). EF Core uses IQueryable heavily.
Q77. What does the Include() method do in EF Core?
Include() is used for Eager Loading. It tells EF Core to fetch related entities in a single SQL query using JOINs. E.g., _context.Departments.Include(d => d.Employees) loads departments and their employees together.
Q78. How do you handle cascade deletes?
If an entity is deleted, its related children should be deleted to prevent orphaned records. We handled this manually in the DepartmentsController by checking and removing associated Services, Employees, and Complaints before deleting the Department.
Q79. What is a Primary Key in EF Core?
A primary key uniquely identifies a record. In EF Core, a property named Id or [ClassName]Id is automatically configured as the primary key. We can also use the [Key] attribute explicitly.
Q80. What is a Foreign Key in EF Core?
A foreign key links a table to another. E.g., Employee.DNo links to Department.DNo. In EF Core, we define the ID property and a navigation property (e.g., public virtual Department Department { get; set; }).
Q81. What is the FromBody attribute?
[FromBody] tells the ASP.NET Core model binder to read the incoming data from the HTTP request body (usually JSON) and map it to the specified parameter (e.g., a DTO object).
Q82. What does Seed Data mean?
Seeding data means populating the database with initial values (e.g., a default Admin account). We created a SeedController to insert an Admin, default Services, and sample users if the tables are empty.
Q83. How do you handle validation in the backend?
We validate incoming DTOs. ASP.NET Core automatically returns a 400 Bad Request if standard binding fails. We also manually check constraints, e.g., checking if an email already exists before registration: _context.Citizens.AnyAsync(c => c.Email == email).
Q84. What is the role of Status Codes?
HTTP status codes inform the client about the result. 200 = OK, 201 = Created, 400 = Bad Request, 401 = Unauthorized, 403 = Forbidden, 404 = Not Found, 500 = Internal Server Error.
Q85. What is a Nullable type?
In C# 8+, reference types are non-nullable by default. Adding a ? (e.g., string? Emoji) allows the variable to hold a null value, reflecting an optional column in the database.
Q86. How does Google OAuth integration work on the backend?
The frontend sends a Google JWT credential. The backend sends an HTTP GET request to https://www.googleapis.com/oauth2/v3/userinfo with this token to verify its validity and fetch the user's Google email and name.
Q87. What is Swagger?
Swagger is a tool integrated into ASP.NET Core that automatically generates a UI to interact with and test your REST API endpoints. It is available at /swagger during development.
Q88. What is the role of the [ApiController] attribute?
It enables API-specific behaviors like automatic HTTP 400 responses for model validation errors, requiring attribute routing, and automatically inferring binding sources (like [FromBody]).
Q89. What is a Migration in EF Core?
Migrations are a way to keep the database schema in sync with the EF Core models. When we change a model, we run dotnet ef migrations add to generate a C# script defining the schema changes, and dotnet ef database update to apply them to SQL.
Q90. What is the MigrationHistory table?
It is a special table created by EF Core in the database (__EFMigrationsHistory) to track which migrations have already been applied, preventing duplicate executions.
Q91. What happens if a migration fails?
You can revert the migration using dotnet ef migrations remove to delete the unapplied migration files, fix your C# models, and then generate a new migration.
Q92. How do you handle many-to-many relationships?
In EF Core, you create a junction table. For example, a Bill can have many Services, and a Service can be on many Bills. We created BillService with a composite or unique structure linking BillId and ServiceId.
Q93. What is the difference between Add(), Update(), and Remove() in EF Core?
Add() marks a new entity for insertion. Update() marks an entity as modified (for an UPDATE query). Remove() marks an entity for deletion. Nothing hits the DB until SaveChangesAsync() is called.
Q94. Why use SaveChangesAsync() instead of SaveChanges()?
SaveChangesAsync() is asynchronous. It doesn't block the thread while waiting for the database to complete the transaction, which makes the web server handle more concurrent requests efficiently.
Q95. What is the difference between FirstOrDefault and SingleOrDefault?
FirstOrDefault returns the first matched record or null if none match. SingleOrDefault expects exactly 0 or 1 match; if multiple records match, it throws an exception. We mostly use FirstOrDefaultAsync.
Q96. What is a DbContextOptions?
It is used to configure the DbContext. In Program.cs, we use it to specify that EF Core should use Npgsql (PostgreSQL provider) and provide the connection string.
Q97. How does error handling work in your API?
We use try-catch blocks in complex controllers. When an exception occurs, we return a BadRequest or StatusCode(500) with the error message. ASP.NET Core also has global exception handling middleware.
Q98. What is the difference between an API Controller and an MVC Controller?
MVC controllers return HTML Views. API controllers return raw data (usually JSON) and use the [ApiController] attribute. We built an API, so the frontend React app handles the UI.
Q99. What are Environment Variables in ASP.NET Core?
They define the environment (Development, Production, etc.). Development mode enables detailed error pages and Swagger. We can also load secrets from OS environment variables instead of hardcoding them.
Q100. Why do we trim inputs?
In the backend, trimming removes accidental leading/trailing spaces (e.g., dto.Title.Trim()) before saving to the DB. This prevents issues like duplicate checks failing due to an extra space.
⚡ SECTION 3: POSTGRESQL & DATABASE (Q101–Q120)
Q101. What is PostgreSQL?
PostgreSQL is a powerful, open-source object-relational database system. It uses and extends the SQL language and is known for its reliability, robust feature set, and high performance.
Q102. Why use PostgreSQL over MySQL?
PostgreSQL is strictly SQL-compliant, handles complex queries better, supports advanced data types like JSONB, arrays, and geometric types, and is highly extensible compared to MySQL.
Q103. What is pgAdmin?
pgAdmin is the most popular open-source administration and development platform for PostgreSQL. It provides a graphical interface to manage databases, run SQL queries, and view tables.
Q104. What is a Primary Key?
A Primary Key is a column (or set of columns) that uniquely identifies each row in a table. It must contain UNIQUE values, and cannot contain NULL values. Every table should have a primary key (e.g., Id).
Q105. What is a Foreign Key?
A Foreign Key is a field in one table that uniquely identifies a row of another table. It is used to establish and enforce a link between the data in the two tables (e.g., DNo in Employee table references DNo in Department table).
Q106. What is Normalization?
Normalization is the process of organizing data to minimize redundancy. We divide large tables into smaller, related tables (e.g., separating Departments from Employees so department names aren't repeated in every employee record).
Q107. What are the common data types in PostgreSQL?
  • integer, bigint — whole numbers
  • numeric, decimal — exact fractions (used for Salary/Rates)
  • text, varchar — strings
  • boolean — true/false
  • timestamp without time zone — dates and times
Q108. What is a SERIAL column?
SERIAL is a pseudo-type in PostgreSQL that creates an auto-incrementing integer column. EF Core automatically configures primary keys (like Id) to use the SERIAL generation strategy so we don't have to provide the ID manually.
Q109. What is a Connection String?
A connection string contains the information needed to connect to the database. Example: Host=localhost;Database=EMunicipalDb;Username=postgres;Password=admin123;. It is stored in appsettings.json.
Q110. How does EF Core communicate with PostgreSQL?
EF Core uses a provider called Npgsql.EntityFrameworkCore.PostgreSQL. This provider translates EF Core LINQ queries into PostgreSQL-specific SQL syntax.
Q111. What is an Entity-Relationship (ER) Diagram?
An ER diagram is a flowchart that illustrates how entities (like Citizen, Complaint, Department) relate to each other within a system. We used it to design the database before coding.
Q112. Explain the relationship between Service and Bill.
It is a Many-to-Many relationship. One Bill can include multiple Services (Water, Tax), and one Service can appear on multiple Bills. This is resolved using a junction table called BillService.
Q113. Explain the relationship between Citizen and Complaint.
It is a One-to-Many relationship. One Citizen can file multiple Complaints, but each Complaint belongs to exactly one Citizen.
Q114. What are Constraints in PostgreSQL?
Constraints are rules applied to data columns. Examples:
  • NOT NULL (field cannot be empty)
  • UNIQUE (no duplicate values)
  • PRIMARY KEY
  • FOREIGN KEY (referential integrity)
Q115. What is a JOIN in SQL?
A JOIN is used to combine rows from two or more tables based on a related column. EF Core handles this automatically when we use the .Include() method, writing INNER JOIN or LEFT JOIN behind the scenes.
Q116. What happens if you delete a Department that has Employees?
By default, PostgreSQL will throw a Foreign Key Constraint violation error, preventing the deletion to protect data integrity. In our backend, we handled this by writing logic to first delete the Employees, then delete the Department (Cascade Delete).
Q117. What is the difference between Timestamp with and without time zone?
timestamp without time zone stores exact date and time exactly as given, ignoring time zones. timestamp with time zone converts the stored time to UTC. We explicitly used timestamp without time zone in our latest migrations to prevent UTC conversion errors in EF Core.
Q118. Can you store images directly in the database?
Yes, as a bytea (binary) format. However, it makes the database huge and slow. Instead, we store the image files on the server's hard drive (wwwroot/uploads) and only store the string path in the database.
Q119. What does the Npgsql package do?
Npgsql is the .NET data provider for PostgreSQL. It allows C# code to connect to the DB and execute queries. The EF Core wrapper around it allows us to use LINQ instead of SQL.
Q120. How do you view the actual SQL queries generated by EF Core?
When running the application (e.g., via dotnet run), EF Core logs all generated SQL statements to the console. This helps debug what queries are actually running against PostgreSQL.
⚡ SECTION 4: CONNECTIVITY, GENERAL & TRICKY VIVA QS (Q121–Q150)
Q121. How do the frontend and backend connect?
They connect via HTTP requests over the network. The React frontend uses the Axios library to send requests (GET, POST) to the API endpoints exposed by the ASP.NET Core backend (e.g., http://localhost:5000/api/news).
Q122. What happens if the backend is down?
If the backend is not running, API calls will fail with a Network Error. The Axios catch block will trigger, and the frontend will show a toast notification saying "Failed to connect" or similar, but the React app itself will not crash.
Q123. What happens if the database is down?
If PostgreSQL is down, the backend cannot execute queries. The backend will throw a database connection exception and return an HTTP 500 (Internal Server Error) to the frontend.
Q124. How did you test your API without the frontend?
We used Swagger (available at /swagger on the backend URL) and PowerShell scripts (Invoke-RestMethod) to send requests to the API and verify the JSON responses before connecting it to React.
Q125. Why is Git used in this project?
Git is a version control system used to track changes in the code. It allows us to save versions (commits), revert mistakes, and push the code to a remote repository (GitHub) for backup and sharing.
Q126. What is a .gitignore file?
A .gitignore file tells Git which files or folders to ignore and not upload to GitHub. We ignore folders like node_modules (frontend dependencies), bin/obj (backend compiled files), and `.env` (secrets).
Q127. Why do we not commit node_modules?
node_modules is massive and contains all downloaded packages. Instead of uploading it, we upload package.json. Anyone who clones the repo just runs npm install to download the exact same packages.
Q128. What is NPM?
NPM (Node Package Manager) is the package manager for JavaScript. We use it to install libraries like React, React Router, and Axios via npm install. It reads from package.json.
Q129. What is NuGet?
NuGet is the package manager for .NET. We use it to install backend libraries like EF Core, Npgsql, and JWT authentication packages via dotnet add package.
Q130. What happens when a user refreshes the page while logged in?
React state is lost on refresh. However, AuthContext has a useEffect that runs on mount. It checks localStorage.getItem('token'). If the token exists, it decodes the role and user details from the JWT and restores the logged-in state instantly.
Q131. Can a citizen access the Admin dashboard by typing /admin in the URL?
No. The frontend has a Protected Route wrapper. If a citizen tries to access /admin, the route checks their role in AuthContext. Seeing they are not an Admin, it redirects them. Even if they bypass the frontend, the backend API uses [Authorize(Roles="Admin")], so the API will return 403 Forbidden.
Q132. What is 401 Unauthorized vs 403 Forbidden?
401 Unauthorized means the user is not logged in or the token is expired/invalid. 403 Forbidden means the user is logged in, but does not have permission (e.g., a Citizen trying to access an Admin API endpoint).
Q133. What is JSON?
JSON (JavaScript Object Notation) is a lightweight data-interchange format. It is easy for humans to read and write, and easy for machines to parse. Our frontend and backend exchange data exclusively in JSON.
Q134. How do you handle password recovery?
Currently, password recovery is not implemented. Future scope involves sending an OTP or reset link to the registered email address using an SMTP service like SendGrid, verifying the token, and updating the password hash.
Q135. What is the difference between client-side and server-side rendering?
In Server-Side Rendering (SSR), the server generates HTML and sends it to the browser. In Client-Side Rendering (CSR), the server sends empty HTML and a large JS bundle; the browser runs the JS (React) to generate the UI. Our app is a Single Page Application (SPA) using CSR.
Q136. What is the advantage of a Single Page Application (SPA)?
SPAs don't require full page reloads when navigating. Only the necessary data is fetched via API (JSON), making the app feel incredibly fast and responsive, like a native desktop app.
Q137. How did you ensure the application is responsive?
We used CSS Flexbox and CSS Grid to create fluid layouts. Media queries are used to adjust styles on smaller screens. Elements have percentages or max-width instead of fixed pixel widths.
Q138. What is the purpose of the Fallback Array in the News Ticker?
The FALLBACK_NEWS array contains default strings. If the backend is down, or there are zero active news items, the frontend displays the fallback array. This guarantees the UI (the red ticker bar) never looks broken or empty.
Q139. Why did you use CSS-in-JS instead of external CSS files?
CSS-in-JS keeps styles scoped to the component and avoids global CSS conflicts. It allows passing dynamic values (like col === 'red' ? '#f00' : '#00f') directly into styles based on component state.
Q140. What is a Promise in JavaScript?
A Promise represents the eventual completion (or failure) of an asynchronous operation. Axios methods like api.get() return Promises. We use await to wait for the Promise to resolve.
Q141. What is an interceptor in Axios?
An interceptor is middleware for Axios. We configured a request interceptor to automatically grab the JWT token from localStorage and attach it to the Authorization: Bearer header for every outgoing API request.
Q142. How do you handle Dates in your project?
The database stores dates as timestamp without time zone. The backend sends dates in ISO 8601 string format (e.g., "2026-04-28T10:00:00"). The frontend parses this using new Date(string).toLocaleDateString() to display it beautifully.
Q143. Can a user have multiple roles?
In our current design, a single account cannot. Admin, Employee, and Citizen are stored in separate tables. If someone works at the municipality and lives there, they need separate accounts for Employee and Citizen portals.
Q144. How does the delete confirmation work on the frontend?
Instead of the native window.confirm() which can be blocked by browsers, we built a custom React Modal component. When "Delete" is clicked, it sets confirmDelete = itemId, showing the modal. Clicking "Yes" in the modal calls the API and hides the modal.
Q145. What happens if a user submits a form without required fields?
HTML5 required attributes prevent submission. If bypassed, the frontend handleSubmit function checks if fields like Title.trim() are empty and shows an error toast. If that is also bypassed, the Backend DTO validation rejects the request with a 400 Bad Request.
Q146. How do you track the total number of complaints?
The backend Admin dashboard endpoint queries the database using LINQ: _context.Complaints.CountAsync(). This is sent to the frontend to display in the statistic cards.
Q147. What was the most challenging part of the project?
(Suggested Answer) Connecting the frontend and backend, handling CORS issues, configuring the JWT authentication correctly so state persists on refresh, and managing cascade deletions when removing a department.
Q148. How do you plan to scale the database if data grows?
PostgreSQL is highly scalable. We can add indexes to frequently searched columns (like Email or Status), use connection pooling on the backend, and eventually move images to cloud storage (like AWS S3) instead of local folders.
Q149. Why didn't you use Redux for state management?
Redux adds a lot of boilerplate code. For our project's scale, React's built-in Context API and useState were sufficient and much easier to implement and maintain for handling authentication and simple component states.
Q150. What is the final conclusion of your project?
The E-Municipal Portal successfully digitizes manual government processes. It provides a secure, role-based, and highly responsive platform that saves time for citizens, reduces paperwork for employees, and gives administrators complete control over municipal operations.
